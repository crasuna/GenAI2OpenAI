# 学校网页联网模式

新增模型 `deepseek-pro-search`（本地功能别名，不是学校新增的基础模型），上游仍调用 `deepseek-pro`。DSH 已在原学校供应商内添加“学校 DeepSeek（联网）”，地址和凭据沿用原配置。选择普通 `deepseek-pro` 则保持原聊天与客户端工具行为。

## 使用

在 DSH 新对话的模型菜单选择“学校 DeepSeek（联网）”。联网与本地工具可以在同一任务中使用：反代接管 web_search，调用学校搜索，将结果交回模型继续决策；read、write、pwsh 等调用仍返回 DSH 执行，沿用 DSH 的沙箱与审批。此模式不需要另外配置官方 DEEPSEEK_API_KEY。普通 deepseek-pro 不接管客户端 web_search。

API 使用原有 `/v1/chat/completions`，仅将 model 改为 `deepseek-pro-search`；支持 stream true/false。有 tools 且 tool_choice 不是 none 时进入搜索与工具决策循环；没有工具或 tool_choice=none 时直接调用学校网页联网问答。required 和指定本地工具沿用提示词约束，不再因联网模式返回 400。

决策步骤使用普通 deepseek-pro；只有模型生成 web_search 才启用 netGo。搜索请求只发送模型生成的查询，不把整段工具历史直接当搜索词。单个请求最多三轮内部搜索，每轮最多三个调用、每个调用一至三个查询；达到上限返回错误。模型若混合输出搜索和本地操作，先处理搜索，再要求模型重新决策，本地操作不会提前执行。搜索完成后，required 或指定 web_search 的约束释放为 auto。

## 网页依据

2026-10-28 读取学校公开首页与其实际引用的聊天前端：

- https://genai.shanghaitech.edu.cn/js/app.621d318c.js
- https://genai.shanghaitech.edu.cn/js/chunk-a18ada4c.33973756.js

网页“联网搜索”绑定 tag1，聊天请求带 netGo: tag1，当前问题在 chatInfo，历史在 messages。回答完成后 POST `/htk/chat/net/search`，使用同一请求体获取参考面板 result.links 和 result.count。

实测 netGo=true 但 chatInfo 为空时，参考结果为 links:null、count:0，正文也出现错误域名。因此直接联网问答将末尾连续 user 消息合并到 chatInfo，其余保留为历史，不重复当前问题。Agent 模式会单独生成查询，从而避免把 DSH 附加的运行环境当作当前搜索问题。

## 参考来源

反代保留模型正文中的链接。另在非流式响应顶层、或 SSE 最后一个完成块顶层增加 `search_results`。直接问答结构为 `{"links":[...],"count":N}`；Agent 模式为 `{"searches":[{"query":...,"answer":...,"sources":...}]}`。参考接口不可用时 sources 含 error，已生成答案仍保留。这个扩展字段不是 OpenAI 标准字段，DSH 不一定显示它。搜索后返回本地工具调用时，还将搜索记录放入 assistant.content，以便 DSH 下一轮回传工具结果时仍保留搜索依据；因此界面可能显示较长的搜索记录。目前没有复刻学校的独立参考来源侧栏。

参考接口返回的列表与模型正文链接在实测中不完全一致，不能把其 num 当作正文逐条引用的可靠映射，也不能据此保证答案事实正确。没有把额外列表伪装成模型实际引用。
