# 学校原生工具调用核查（2026-10-28）

## 结论

当前已接入的 /htk/chat/start/chat 未在本次测试中返回结构化 tool_calls 或 function_call，不能启用原生工具透传。此结论限于已测试的入口和参数，不代表底层模型不支持工具，不排除其他未公开服务入口。生产反代保持原样，测试未执行任何工具。

## 方法与结果

使用本人授权的学校 Token，合成 lookup_test_code(label) 工具，参数仅为测试标签 ALPHA。不提供文字模拟工具提示词，不发送私人文件或旧 DSH 对话。直接检查学校原始响应，不经过本机正文提取器，避免反代漏读字段造成假阴性。

DeepSeek（deepseek-pro）与 GPT（gpt-6.1-sol）各测试 6 种组合，共 12 次：

| 方式（每种两个模型） | 结果 |
| --- | --- |
| 顶层 tools + tool_choice=required，问题放 chatInfo | 普通文字，finish_reason=stop，无结构化调用 |
| 顶层 tools + 指定函数，问题放 chatInfo | 普通文字，finish_reason=stop，无结构化调用 |
| 顶层 tools + tool_choice=none 对照 | 普通文字，finish_reason=stop，无结构化调用 |
| 顶层 tools + 指定函数，问题放 messages | 普通文字，finish_reason=stop，无结构化调用 |
| 旧版 functions + function_call 指定函数 | 普通文字，finish_reason=stop，无结构化调用 |
| tools + 指定函数，stream=false | HTTP 200 但业务 success=false/code=500，系统内部错误 |

多数普通回复表示测试工具不可用；一个旧版 functions 测试回复声称要调用并给出参数 JSON，但内容仍在正文，不是实际结构化调用。模型的自述不作为支持能力的证明。现象与学校转换层未传递或未处理这些字段相符，但没有后端日志证明内部原因。
